# Naruto-Windows v1.1.0 — BR Session Recovery

## What changed

- `src/main/web-login.ts` now attempts an optional BR session recovery before the
  embedded login window. It reads `br-session-recovery.json` from the app user
  data directory, restores the official CEF cookies, fetches the signed
  `main.html` entry, and creates the normal Flash BrowserView through
  `GameSessions.create()`.
- `src/main/br-session-recovery.js` is the packaged recovery module. It validates
  the server-bound launch URL and never mutates the Electron session before the
  portal response and URL validation succeed.
- `scripts/br-cookie-reader.ps1` reads the official CEF Cookies database through
  `winsqlite3.dll` (plaintext values only; read-only).
- `scripts/br-portal-fetch.ps1` fetches the portal through Microsoft Edge
  (CDP). Node HTTPS is rejected by Cloudflare on the BR portal, while Edge is
  accepted and the server-list HTML contains the signed `main.html` URL.
- `scripts/windows-package.mjs` includes the recovery module, both PowerShell
  helpers, and the bundled Flash runtime in the portable resource manifest.
- `runtime/flash-34/PepperFlashPlayer.dll` is the patched x64 Flash 34.0.0.242
  runtime. The system-installed 34.0.0.380 displays the Adobe end-of-life
  dialog. `runtime/` is gitignored (proprietary runtime), so the file must be
  supplied locally before packaging.

## Build

```powershell
cd Naruto-Windows
npm install
npm run typecheck
npm run build
npm test
npm run package:windows
```

The build requires these local (gitignored) files:

```text
runtime/flash-34/PepperFlashPlayer.dll
runtime/flash-34/version.json
```

## Verification status

- `typecheck` / `build` / unit tests: see the release commit.
- Portable first live BR login: PASS. The signed entry was fetched through Edge,
  cookies were injected into `persist:naruto-br-1`, and the existing BrowserView
  rendered the Flash game UI.
- Second live login: blocked by a temporary Cloudflare 403 on the test network
  after repeated portal requests. The app now preserves the recovered session
  and shows a retry notice instead of opening the blocked login window.

## Known limitations

- The BR portal is protected by Cloudflare. If Edge receives a 403, wait for the
  cooldown and retry; the helper fails closed and never writes a partial session.
- The bundled Flash DLL is a patched third-party runtime (Authenticode
  `HashMismatch`). It is loaded only from the app's own `runtime` directory.
- The official CEF profile must be logged in to the target BR account before the
  app is started; the official client must be fully exited so CEF checkpoints
  the Cookies database.
- Set `NARUTO_BR_SESSION_RECOVERY=0` to disable the optional recovery path.
